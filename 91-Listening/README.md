# 听音默写 · 独立背词项目

每日取 `90-ReviewApp` 当天实际生成的词表，共用本地单词音频，但进度、成绩与普通四关背词分别保存。打开 `listening.html`，点“开始 / 继续”后，只有单词声音，不提前显示单词、音标或中文释义。

## 做题规则

- 每词填写英文和中文；英文忽略大小写、首尾空格，但检查正确拼写。
- 中文写对任意一个义项即可。原词义拆分、人工整理的同义/近义说法、构建时模型补充的简写共同作为可接受答案；忽略常见标点、词性括号和末尾“的”。
- 不用任意子串或编辑距离放行中文，以免“不可靠”被当作“可靠”，或只输入“库”就通过“数据库”。
- 提交后才显示标准词、原释义和部分可接受说法；任一项未通过，该词会隔三词再练，直到中英文都正确。
- “没想起来，看答案”也会安排重练。音频缺失时可暂时跳过；完成页可以再练跳过的词。
- 某个正确近义说法仍可能没被收录：按用户要求显示答案后重新练，不自动当作答对。可在 `aliases.json` 中持续补充简短说法。

## 每日构建

普通 `90-ReviewApp/build_review.py --date YYYY-MM-DD` 现在会同时更新本项目。普通页面顶部和此页之间有互相跳转的入口。

独立重建某一天（只读原词表，不推进普通背词游标）：

```sh
python3 build_listening.py --date 2026-11-12
python3 build_listening.py --date 2026-11-12 --offline
```

`--offline` 只读已有音频和中文答案，不请求外部服务。普通构建的 `--no-listening` 可以跳过本项目，`--mock` 不写本项目。

新词的近义释义在构建时通过现有私有 DeepSeek 配置补充，并按英文词与完整原释义缓存到 `aliases_cache.json`。失败时保留原释义、人工替代表达，背词仍可使用；答题时不调用模型，不把 API key 放进网页。

## 文件与进度

- `template.html` / `listening.html`：模板与当前词表页面。
- `answer_matcher.js`：中英文判定逻辑，构建时直接内嵌，离线可用。
- `aliases.json`：人工整理的可接受中文说法；当前已覆盖 11-12 的 30 词。
- `days/day_YYYY-MM-DD.json`：按日期保存本项目词表与中文答案范围。
- 浏览器存储前缀 `cet6-listening:v1:`，按日期及词集保存练习进度，与普通项目分开；换浏览器不会带走进度。
- 成绩导出名 `listening_session_YYYY-MM-DD.json`，带 `kind: listening`，统计答题记录、正确/跳过词数和耗时；普通 `sync_session.py` 会拒绝同步这种文件，防止误写 SM-2 和新词游标。

音频引用 `../90-ReviewApp/.audio_cache/`，继续仅保存在本机，不进入 GitHub。打开页面默认安静，点击开始后才播放，转入后台会停止当前声音。

## 验证

`node tests/test_matcher.cjs` 验证近义接受与否定/子串反例。普通项目的 Python 测试另覆盖生成隔离、词义改变后的缓存失效和同步拒绝。

已在隔离、静音 Chrome 中验证完整答题、错词重练、独立导出、恢复与缺音频跳过；没有改动用户的学习记录或在 Downloads 留测试成绩。
